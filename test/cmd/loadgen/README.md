# Accumulate Load Generator

A comprehensive load testing tool for the Accumulate protocol that exercises the full range of operations.

## Features

- **Configurable TPS**: Set target transactions per second
- **Operation Mix**: Configure percentage distribution of different operations
- **Ramp-up Schedule**: Gradually increase load to target TPS
- **Hot-reload Configuration**: Update settings without restarting
- **Comprehensive Metrics**: Track success rate, latency, and per-operation statistics
- **Multi-BVN Distribution**: Operations distributed across all network partitions

## Supported Operations

1. **Token Transfers**
   - Lite-to-lite transfers
   - Lite-to-ADI transfers
   - ADI-to-ADI transfers

2. **Key Management**
   - Key rotation (UpdateKeyPage)
   - Create key pages
   - Create key books

3. **Account Operations**
   - Create identities (ADI)
   - Create token accounts
   - Create data accounts

4. **Data Operations**
   - Write to data accounts
   - Lite data account operations

5. **Synthetic Transactions**
   - Automatically generated by protocol

## Usage

### Basic Usage

Run with default configuration:

```bash
go run test/cmd/loadgen/main.go
```

### With Custom Configuration

```bash
go run test/cmd/loadgen/main.go -config config.json
```

### Configuration File

Create a JSON configuration file (see `config.example.json`):

```json
{
  "serverUrl": "http://127.0.1.1:26660",
  "targetTps": 100,
  "duration": 60,
  "rampUpSeconds": 10,
  "reloadInterval": 30,
  "operationMix": {
    "token-transfer-lite": 30,
    "token-transfer-adi": 20,
    "write-data": 20,
    "create-account": 10,
    "key-rotation": 10,
    "create-keypage": 5,
    "create-keybook": 5
  }
}
```

### Configuration Parameters

- `serverUrl`: Accumulate API endpoint (default: "http://127.0.1.1:26660")
- `targetTps`: Target transactions per second (default: 100)
- `duration`: Test duration in seconds (default: 60)
- `rampUpSeconds`: Ramp-up period to reach target TPS (default: 10)
- `reloadInterval`: How often to reload config file in seconds (default: 30)
- `operationMix`: Weighted distribution of operations (values are relative weights)

### Operation Mix

The `operationMix` field controls the distribution of transaction types. Values are relative weights, not percentages. For example:

```json
"operationMix": {
  "token-transfer-lite": 50,
  "write-data": 30,
  "create-account": 20
}
```

This creates a mix where:
- 50% of transactions are lite token transfers
- 30% are write-data operations
- 20% are account creation operations

### Hot Configuration Reload

When running with a config file, the load generator automatically reloads the configuration at the specified `reloadInterval`. This allows you to adjust the operation mix and TPS without restarting the test.

To adjust settings during a test:
1. Edit the configuration file
2. Save the changes
3. Wait for the next reload interval (or send SIGHUP)

## Output

### Log File

All output is written to `/tmp/load-generator.log`:

```bash
tail -f /tmp/load-generator.log
```

The load generator reports metrics every 10 seconds:

```
  write-data: 200 transactions (avg: 189ms, min: 95ms, max: 650ms)
  create-account: 100 transactions (avg: 456ms, min: 230ms, max: 1340ms)
  key-rotation: 100 transactions (avg: 334ms, min: 180ms, max: 890ms)
  create-keypage: 50 transactions (avg: 401ms, min: 210ms, max: 950ms)

```

### Metrics Collected

- **Total Submitted**: Number of transactions submitted
- **Total Succeeded**: Number of successful transactions
- **Total Failed**: Number of failed transactions
- **Success Rate**: Percentage of successful transactions
- **Per-Operation Metrics**:
  - Transaction count
  - Average latency (milliseconds)
  - Minimum latency
  - Maximum latency

## Architecture

### Account Initialization

The load generator creates:
- 10 lite token accounts (funded via faucet)
- 5 ADI accounts with token accounts (funded from lite accounts)

All accounts are pre-funded with tokens and credits to ensure operations can execute.

### Transaction Distribution

Transactions are distributed across:
- Multiple account types (lite and ADI)
- All network partitions (BVNs)
- Various operation types based on configured mix

### Concurrency

The load generator uses:
- Per-second batching to achieve target TPS
- Goroutine pool for parallel transaction submission
- Atomic counters for thread-safe metrics

## Troubleshooting

### Insufficient Credits

If operations fail due to insufficient credits, the load generator will log errors. The initialization phase should fund accounts, but high-volume testing may require increasing initial funding.

### Network Congestion

If success rate drops below 95%, consider:
- Reducing target TPS
- Increasing ramp-up period
- Checking network health

### Configuration Reload Issues

If configuration changes don't take effect:
- Check `/tmp/load-generator.log` for reload errors
- Verify JSON syntax in config file
- Ensure file permissions allow reading
