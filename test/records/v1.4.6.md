### Required for a working node, not healing

`internal/database/snapshot/restore.go` +34, `full.go`, `batch.go` +5 — restores
`UpdateBPT()` before `Commit()`. Without it, any restore that refreshes the write
batch more than once leaves accounts missing from the BPT, which on a live
network is an app-hash mismatch against every other node.

### Not healing — inherited from `main`, reviewed and knowingly kept

Audited before tagging; the release was **kept as-is** rather than re-cut as
`v1.4.4.2` + healing only, which would have re-opened the lineage split `!1163`
had just closed.

- **`pkg/build/adi_account.go` — `math/rand` → HKDF-SHA256 seed derivation
  (`#3877`). This changes the key derived from a given seed.** A seed that
  produced one key under `v1.4.4.2` produces a different key here. It is a
  legitimate entropy fix, and it is the one behavioural change in this release
  that a reader of the tag message would not expect. Recorded here because the
  tag message does not mention it.
- `pkg/api/v3/message/dial.go` — mutex around the stream map (race fix). Linked
  into `accumulated` and present in the executor's dependency graph, though the
  change itself is in the P2P transport.
- `pkg/api/v3/p2p/peerdb/db.go`, `pkg/database/snapshot/format.go`,
  `pkg/crypto/alternatives.go` — `gosimple`/gofmt/`nolint` comments only, zero
  behaviour change.

## `#4073` validation

Controlled A/B in docker, identical config, only the reconcile differing:
without it 16 messages were lost permanently; with it none were, and 129 pulls
were logged. Unit coverage in `test/e2e/synth_heal_test.go` —
`TestSyntheticHealingLostPrefix` and `TestReconcileDoesNotRaceNormalDelivery`,
the latter asserting **zero** reconcile attempts when nothing is dropped (red at
34 before the grace period was added, green at 0 after).

## NOT covered — read before deploying

- **No Vandenberg soak.** Mainnet runs `v2-vandenberg`, where `#4070` is
  inactive by design. Every soak to date ran at `v2-jiuquan`. This is the one
  untested corner before mainnet and is cheap to close with the same harness.
- **No completed 24h soak on this exact tree.** The `#4073` evidence is from
  5-minute controlled A/B runs, not a long burn-in.
- **The state-root fix is not soak-covered.** Only the unit-level
  `TestExecutorConsistency` exercises it. No restore of a mainnet-sized snapshot
  has been performed.
- **The HKDF seed-derivation change has no migration path.** Anyone who derived
  a key from a seed under an earlier build gets a different key here.
- **Deployment ordering is a hard constraint.** `v1.4.4.2` enables Jiuquan
  *without* `#4070`. Every node must run `v1.4.5`+ **before** Jiuquan is
  activated, or the first late-anchor synthetic produces divergent recorded state
  and the network halts on an app-hash mismatch. Activation is a separate,
  scheduled step.
