### Known flaky tests (not defects in this release)

- **`TestEIP712Arrays`, `TestEIP712MessageForWallet`** — failed attempt 1 with
  `exit status 1`; passed 2/2 when re-run per-package. Cause:
  `test/cmd/eth_signTypedData/execute.sh` runs `npm ci` on *every* invocation,
  and the test calls it once per subtest, so parallel subtests race on the same
  `node_modules`. Worth fixing in the harness (install once, or lock).
- **`TestValidateAPI`** — failed an earlier full run with
  `no live peers for query:bvn1`; passed 3/3 on re-run. P2P service discovery
  timing in the test harness.

### Fixed during this release

- **`TestExecutorConsistency`** — had been failing on `main` since `6879d19ff`
  and was the only test catching the wrong-state-root bug fixed in `939e45f52`.
  Now passes.
- **`TestMigrateOld`** — golden expected `enable-healing = false`; updated with
  the removal of the healing flags.

## NOT covered — read before deploying

- **No completed 24h soak on this tree.** The run on this code
  (`test/docker/synth-heal/soak/runs/20260725T233615Z/`) was stopped at 4.96h of
  24h to free the machine for the release build. The 20h Run 5 evidence in
  `soak-results.md` is from the dagbft lineage, not this one.
- **No docker harness test against this image.** `synth-heal/run-test.sh`,
  the `mixver` interop test, and `onevalidator` were not run on `v1.4.5`.
- **The state-root fix is not soak-covered.** `939e45f52` changes snapshot
  restore, and only the unit-level `TestExecutorConsistency` exercises it. A
  restore of a real mainnet-sized snapshot has not been performed.
- **No Vandenberg soak.** Mainnet runs `v2-vandenberg`, where `#4070` is
  inactive by design. Every soak to date ran at `v2-jiuquan`.
- **Deployment ordering is a hard constraint.** `v1.4.4.2` enables Jiuquan
  *without* `#4070`. Every node must run `v1.4.5`+ before Jiuquan is activated,
  or the first late-anchor synthetic produces divergent recorded state and the
  network halts on an app-hash mismatch. Activation is a separate step.
