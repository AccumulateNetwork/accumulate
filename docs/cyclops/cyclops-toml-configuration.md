# TOML Configuration Files Documentation

## 📋 **Overview**

This directory contains all TOML configuration templates used in Cyclops validator deployment. These files are critical for node operation and must be preserved as they define network behavior, partition configuration, and CometBFT consensus parameters.

---

## 🚨 **CRITICAL WARNING**

**DO NOT LOSE THESE FILES!** They are generated through complex processes and recreating them requires:
- Deep understanding of Accumulate network architecture
- Proper partition configuration
- CometBFT consensus parameter tuning
- Network-specific settings

---

## 📁 **TOML File Inventory**

### **1. accumulate-template-bvn.toml**
- **Purpose**: Block Validator Network (BVN) partition configuration template
- **Generated By**: Phase 1 preparation script (`phase1-prep.sh`)
- **Source**: Created from network JSON configuration via `accumulated init` command
- **Deployed To**: `.accumulate/bvn-cyclops/config/accumulate.toml`

**Key Configuration**:
```toml
[describe]
  type = "blockValidator"
  partition-id = "bvn-cyclops"

[network]
  id = "cyclops"
```

### **2. accumulate-template-dn.toml**
- **Purpose**: Directory Network (DN) partition configuration template  
- **Generated By**: Phase 1 preparation script (`phase1-prep.sh`)
- **Source**: Created from network JSON configuration via `accumulated init` command
- **Deployed To**: `.accumulate/dn/config/accumulate.toml`

**Key Configuration**:
```toml
[describe]
  type = "directory"
  partition-id = "Directory"

[network]
  id = "cyclops"
```

### **3. config-template-cometbft.toml**
- **Purpose**: CometBFT consensus engine configuration template
- **Generated By**: CometBFT initialization during `accumulated init`
- **Source**: CometBFT default configuration with Cyclops-specific modifications
- **Deployed To**: `.accumulate/dn/config/config.toml` and `.accumulate/bvn-cyclops/config/config.toml`

**Key Sections**:
- **Proxy App**: `proxy_app = "tcp://127.0.0.1:26658"`
- **Moniker**: `moniker = "cyclops-validator"`
- **P2P Configuration**: Network discovery and peer connections
- **Consensus Parameters**: Block timing, transaction limits
- **RPC Configuration**: API endpoints and security

### **4. tendermint-template.toml**
- **Purpose**: Legacy Tendermint configuration (compatibility)
- **Generated By**: CometBFT initialization process
- **Source**: Generated during node initialization
- **Deployed To**: `.accumulate/dn/config/tendermint.toml` and `.accumulate/bvn-cyclops/config/tendermint.toml`

---

## 🔧 **Generation Process**

### **Phase 1: Template Creation**
1. **Network JSON Processing**: `cyclops-network.json` → Configuration structs
2. **Accumulate Config Generation**: Network settings → `accumulate.toml` templates
3. **CometBFT Config Generation**: Consensus parameters → `config.toml` template
4. **Template Validation**: Syntax and structure verification

### **Phase 2: Deployment Customization**
1. **Partition-Specific Copies**: Templates copied to partition directories
2. **Dynamic Configuration**: Port assignments, peer lists, validator keys
3. **File Permissions**: Security settings applied (600 for configs)
4. **Structure Validation**: Directory hierarchy and file placement

### **Dual-Node Directory Structure**
```
.accumulate/
├── config/
│   ├── accumulate.toml          # Root config (legacy)
│   └── config.toml              # Root CometBFT config
├── dn/                          # Directory Network
│   └── config/
│       ├── accumulate.toml      # DN partition config
│       ├── config.toml          # DN CometBFT config
│       └── tendermint.toml      # DN legacy config
└── bvn-cyclops/                 # Block Validator Network
    └── config/
        ├── accumulate.toml      # BVN partition config
        ├── config.toml          # BVN CometBFT config (modified ports)
        └── tendermint.toml      # BVN legacy config
```

## 🔍 **Source Code Origins**

### **Accumulate Configuration**
- **File**: `/cmd/accumulated/run/config.go`
- **Function**: `Config.SaveTo()` - Marshals configuration to TOML
- **Generation**: `/cmd/accumulated/cmd_init_network.go:170`
- **Template**: Network JSON → Go structs → TOML serialization

### **CometBFT Configuration**
- **Source**: CometBFT library default configuration
- **Customization**: Cyclops-specific modifications in init process
- **File**: Generated by CometBFT's `InitFilesWithConfig()`
- **Location**: `/cmd/accumulated/cmd_init.go`

### **Network Configuration Processing**
- **Input**: `cyclops-network.json` (network topology and validators)
- **Processing**: `/cmd/accumulated/cmd_init_network.go:initNetwork()`
- **Output**: Partition-specific TOML configurations

## ⚠️ **Critical Configuration Elements**

### **Partition Type Mapping**
- **Directory Network**: `type = "directory"`, `partition-id = "Directory"`
- **Block Validator Network**: `type = "blockValidator"`, `partition-id = "bvn-cyclops"`

### **Network Identity**
- **Network ID**: `id = "cyclops"` (must match across all configs)
- **Chain IDs**: `cyclops.Directory` and `cyclops.bvn-cyclops`

### **Port Configuration**
- **DN Ports**: 26656 (P2P), 26657 (RPC), 26658 (ABCI)
- **BVN Ports**: 36656 (P2P), 36657 (RPC), 36658 (ABCI)

---

## 🛡️ **Security Considerations**

### **File Permissions**
- **Configuration Files**: 644 (readable by owner and group)
- **Private Keys**: 600 (readable by owner only)
- **Directories**: 755 (accessible by owner, readable by others)

### **Sensitive Information**
- **Validator Keys**: Stored separately in JSON files
- **Node Keys**: Stored separately in JSON files
- **Network Topology**: Public information in TOML configs

## 🔄 **Backup and Recovery**

### **Backup Strategy**
1. **Template Preservation**: Keep original templates in `artifacts2/toml/`
2. **Deployment Copies**: Backup deployed configs before modifications
3. **Version Control**: Track changes to template files
4. **Documentation**: Maintain generation process documentation

### **Recovery Process**
1. **Template Restoration**: Copy from `artifacts2/toml/` directory
2. **Regeneration**: Use Phase 1 script to recreate from network JSON
3. **Validation**: Verify syntax and structure after recovery
4. **Deployment**: Use Phase 2 script to deploy restored configs

## 🚀 **Usage in Deployment**

### **Template Usage**
```bash
# Templates are automatically used by deployment scripts
./phase1-prep.sh      # Generates configs from templates
./phase2-deploy.sh    # Deploys configs to node structure
```

### **Manual Template Application**
```bash
# Copy BVN template to deployment
cp toml/accumulate-template-bvn.toml .accumulate/bvn-cyclops/config/accumulate.toml

# Copy DN template to deployment  
cp toml/accumulate-template-dn.toml .accumulate/dn/config/accumulate.toml

# Copy CometBFT template
cp toml/config-template-cometbft.toml .accumulate/dn/config/config.toml
```
