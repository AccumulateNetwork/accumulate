## How the work was done

Every change on this branch after `1ea77143d` was made by a Claude Code session launched, scheduled and gated by
DTRulesAgents (github.com/PaulSnow/DTRulesAgents), a DTRules decision-table coordinator. The goal (#4205) was
split by an analyst session into nodes, one GitLab issue into a few parts each (`e11.4362a` ... `e11.4362f`).
Every node has a **test node** (`.t`) whose session wrote a failing test first, and a **work node** whose session
made it pass; author and implementer are never the same session. Work nodes rated sensitive or critical got a
review session, and a reviewer's `changes_requested` produced a retry on a stronger model. A node is done when
its check passed at HEAD, its review approved, and the launcher merged its branch into this lead.

Commit titles say what a change makes true, in the form `Issue #NNNN: <statement>`. Commits titled `integrate
e11.<node>...` are the launcher's merges. Every session's transcript, protocol record (`report.log`), captured
test output (`evidence/*.out`) and prompt live on thelio under `~/repos/github.com/PaulSnow/DTRulesAgents/.state/sessions/<session>/`
(116 E11 sessions, ~160 MB); the run's decisions are in `.state/coordinator/decisions.jsonl` and the per-tick
traces beside it. They are not in any repository. What each log is and how to read a node's story: `docs/logs.md` in the DTRulesAgents repository (github.com/PaulSnow/DTRulesAgents).

## What landed, by issue

**#4368 - node states.** A BOOTING node's querier refuses every read with `NotReady` (counted by call); the tracker
promotes only out of BOOTING; the sequencer serves only when ACTIVE. `nodestate` has two states, BOOTING and
ACTIVE; a persisted WAITING maps to BOOTING and COMPLETE to ACTIVE. Found and fixed on the way: `Instance.Stop`
hung on every DAG-BFT node because `Sequencer.captureProvableView` held a read batch that only the next provable
commit replaced; `Sequencer.Close()` now releases it and `dagbft.go` registers it as an instance cleanup
(`aff7148e7`, `b65e2bfae`). A from-genesis node outside the committee follows over gossip, answers reads and relays
a transaction the committee executes (`cdc71922f`).

**#4361 - serving as of an anchored block.** Main's unit tests were ported and caught a refusal-order bug. A
historical page is checked by a leaf and every block against the one above it. A joined node no longer calls its
own gap an absence. **Paul's decision (2026-09-22):** a peer retains and serves an account's *whole* BPT leaf
(main, chain heads, directory, pending, the ledger's delivery queues and events) as of a retained block, for the
accounts that changed in that block, pruned on the same `BPTHistoryDepth` window (`457564f8f`, `80328b3cf`,
`docs/serving-at-an-anchored-block.md`). This is the serving half of option (b) below; the join does not yet use it.

**#4362 - the join converges (a, b, c, d landed; e, f open).**
- *a:* `TestRestartedNodeWithAPopulatedDatabaseResyncs` is live and passes. The pull settles one pass of current
  state once its root is proven by a verified anchor. The proof: a root equals a verified signed anchor's
  `StateTreeAnchor`, or it is held to a later signed anchor through the bpt chain's own history from the earlier
  anchor's `StateTreeAnchor` - nothing is read from a peer's index (the reviewer's forged-`bpt-index` finding is
  closed by that). A verified anchor's `RootChainAnchor`/`RootChainIndex` are kept with its `StateTreeAnchor`. The
  settle bound (`maxSettleRounds`), held passes and the meeting point are gone. Spec: `executor.md` Sync,
  `DIFFERENCES.md` E11.
- *b:* `join.Run` converges on collected blocks and pulled state, hands off where the next block has no gap
  (`Stage.HasGap`), and asks no peer for staging. The daemon joins through `ExecutorStage` and no longer executes
  from its own state. Fixed on the way: a double `StartCollecting` (#4351) - it is idempotent and the buffer's
  first block is read when the first group arrives.
- *c:* the staging API is deleted end to end: `Sequencer.StagingSnapshot`, the private `StagingSnapshot` messages,
  their routing and generated types, `Executor.LoadStaging`, `takeStaging`/`TakeStaging`, `executeFromOwnState`,
  the simulator's staging snapshot; `TestOneValidatorRestartDoesNotDiverge` joins through `join.Run`. The
  simulator's join state is a `join.Buffer`.
- *d:* after the handoff the join checks every executed block's root against its anchored root from the bpt chain;
  on a mismatch it collects again, pulls first and re-converges; a node collecting again after a handoff maps its
  buffer onto the blocks after the one it executed to (pinned on the real `Service`).
- *e (open, test written):* the system ledger records each block's leader round behind an ExecutorVersion gate, so
  the handoff picks buffered groups by round and `collectFrom`/`buffer[skip:]` go. **Paul approved this protocol
  change on 2026-09-23.**
- *f (open, test written, fix committed on its branch):* an overrun during the join is recorded and the join
  resumes from a newer block instead of the daemon abandoning it silently and for ever.

## Decisions Paul made during the run

1. **Q1 (2026-09-21):** "The SIGNED ANCHOR has the anchor and BPT root for a block + the history. All the accounts
   for an anchor are current." No rebuilding of an old block's leaf from parts on the client.
2. **Q2 (2026-09-22):** a joiner may take state as of an anchored block B if the peer serves the whole leaf at B -
   option (b); the serving half landed as #4361's whole-leaf retention.
3. **Option 1 (2026-09-22):** the join lands under the proof it has (anchor equality or bpt-chain history, no peer
   index); the option (b) join is not needed now. The whole-leaf retention stays on the lead, unused by the join,
   as groundwork.
4. **#4362e (2026-09-23):** the leader-round-in-the-ledger protocol change is acceptable.
